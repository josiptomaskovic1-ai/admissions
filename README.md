# Virela Admissions

Independent, one-to-one university-admissions consulting for the Balkans and diaspora.
Single-page, multilingual (bs / sr / hr / en / de) marketing site.

Stack: Next.js 16 (App Router) · React 19 · Vite (`vinext`) · Tailwind 4 · deployed on Cloudflare (Wrangler).

## Develop

```bash
npm install
npm run dev      # vinext dev
npm run lint     # eslint
npm run build    # vinext build
```

## Required environment variables

These are `NEXT_PUBLIC_*` variables, so they are **inlined at build time**. Set them
in the production build environment (Cloudflare / Wrangler build vars) — `.env.example`
is documentation only and is not read by the build.

| Variable | Purpose | If unset |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Absolute production origin used for `metadataBase`, canonical URL, `og:*`, `robots.txt` and `sitemap.xml`. | Falls back to `http://localhost:3000` (fine for dev, wrong for prod). |
| `NEXT_PUBLIC_CAL_LINK` | Cal.com event URL for the booking button. | The booking button falls back to a `mailto:` link. |

## Content & i18n

All copy lives in [`app/content.ts`](app/content.ts) as a `translations` object keyed by
locale. Every locale must expose the same keys (the UI type-checks against the union of
all locales), so add new keys to **all five** locales together.

Locale is currently resolved client-side (localStorage `virela-locale` + `navigator.language`),
so all locales share one URL. SEO note: only the default `bs` skeleton is server-rendered;
per-locale indexing would require moving locale into the URL (e.g. an `app/[locale]` segment
with `generateStaticParams` and per-locale `hreflang`). Tracked as a follow-up.

## Legal

`app/impressum/page.tsx` and `app/privacy/page.tsx` are **templates** with bracketed
placeholders. Complete them with real operator/entity details (and have the privacy policy
reviewed) before publishing — the Impressum is legally required for the German-speaking market.

## Deployment

`.openai/hosting.json` (D1/R2 bindings) is generated by the hosting platform and is
gitignored; `vite.config.ts` loads it defensively so a clean checkout still builds.
Security headers are served via [`public/_headers`](public/_headers); confirm your runtime
honors that file (otherwise apply the same headers via a Worker response or Cloudflare rules).
